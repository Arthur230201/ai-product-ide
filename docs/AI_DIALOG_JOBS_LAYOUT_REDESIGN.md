# AI 对话框布局：乔布斯重设计

> 问题：常驻对话面板固定 380px 导致画布区域被压缩；编辑模式下节点详情与对话并排，空间局促。  
> 原则：**画布优先、一次只做一件事、需要时再展开对话。**

---

## 乔布斯原则

1. **画布是主角**：用户来是为了「想法 → 画布」。画布应获得**最大可用空间**，不被常驻宽面板永久挤压。
2. **对话按需展开**：对话面板默认**折叠为窄轨**（约 48px，仅图标），点击展开为 380px；用完后可收起到窄轨，画布立刻恢复空间。
3. **编辑模式全神贯注**：进入节点详情 = 进入「编辑」上下文。此时**不展示右侧对话面板**，节点详情**全屏宽**，无分栏干扰。
4. **一个焦点**：画布模式 = 画布 + 可展开的对话轨；编辑模式 = 全宽节点详情（其内自有输入与操作）。

---

## 布局方案

### 画布模式（未打开节点详情）

| 状态 | 布局 | 说明 |
|------|------|------|
| **对话折叠（默认）** | 画布占满至右侧 48px；右侧 48px 为「对话」轨，仅显示图标，可点 | 画布有效宽度 ≈ 100vw - 48px，接近全屏 |
| **对话展开** | 画布占满至右侧 380px；右侧 380px 为完整对话面板（历史 + 输入） | 用户主动展开或收到澄清时自动展开 |

- 折叠轨：竖条 48px，深色底，居中显示 MessageCircle 图标；hover 提示「打开 AI 对话」；有未读或等待澄清时可加小圆点。
- 展开后面板顶部提供「收起」按钮，收起后回到 48px 轨。

### 编辑模式（已打开节点详情）

| 布局 | 说明 |
|------|------|
| **节点详情全宽** | 详情层宽度 = 100vw，右侧不预留对话面板 | 编辑时不再与对话分栏，预览与表单获得完整宽度 |
| **对话入口** | 详情内如需与 AI 交互，使用详情自带的 CommandBar（生成 UI、分析等） | 不在此模式展示右侧对话轨，避免双焦点 |

- 实现：当 `isDetailPanelOpen === true` 时，不渲染右侧 aside（既不渲染 48px 轨也不渲染 380px 面板）。NodeDetailPanel 使用 `width: 100vw`。

### 演示模式

- 与现有一致：不展示对话面板与轨。

---

## 状态与行为

- **conversationPanelOpen**：`true` = 右侧展开为 380px 面板，`false` = 右侧为 48px 窄轨（画布模式）或完全不显示（编辑模式）。
- **默认**：`conversationPanelOpen: false`，即画布模式下降默认折叠为轨。
- **自动展开**：当后端返回 `clarification_needed` 时，可 `setConversationPanelOpen(true)`，便于用户看到追问与选项。
- **收起**：用户点击面板内收起按钮 → `setConversationPanelOpen(false)`。

---

## 验收

1. 画布模式、对话默认折叠时，画布可见宽度为 100vw - 48px；点击右侧 48px 轨，面板展开为 380px，可正常对话与输入。
2. 展开后面板有收起控制，收起后恢复 48px 轨。
3. 打开节点详情后，右侧 48px 轨与 380px 面板均不显示，节点详情占满 100vw。
4. 关闭节点详情后，恢复画布模式，右侧仍为轨或展开态（保持用户上次选择）。
