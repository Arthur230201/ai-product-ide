# 国家电网级「文档→知识图谱→智能问答」落地方案
## 最强大脑三轮讨论审计报告

> 模拟乔布斯、马斯克及多领域专家团队，经三轮讨论与审计，形成适用于国家电网级别的完整落地方案。  
> 文档版本：v1.0 | 日期：2026-02-06

---

## 一、议题与约束边界

**核心议题**：在超大型企业（国家电网级）场景下，如何从海量、超大、多格式非结构化文档中抽取知识、建立图谱，并支撑**企业级**智能问答，且满足关基、等保、信创与长期可运营。

**约束边界**：
- **规模**：全网级文档量级（百万~千万级文档）、单文档可达 GB 级
- **合规**：关键信息基础设施、电力行业等保（二级及以上）、信创优先、数据不出域
- **可靠性**：7×24、RTO/RPO 可承诺、审计可追溯
- **国产化**：优先安全可信产品，涉及关基的需通过安全审查

## 二、第一轮讨论：立场与第一性诉求

### 2.1 乔布斯视角（产品与体验第一）

**核心主张**：
- 「用户不关心你有多少节点、多少文档，他们只关心：问得准、答得稳、等得可接受。」
- 若一线员工问「某规程在哪种情况下适用」要等 30 秒或答非所问，再大的图谱也是失败。
- 必须**先定义成功**：回答准确率、首答满意率、P99 延迟、可解释性（可追溯到原文/条款）。

**对技术选型的追问**：
- 图谱是手段不是目的；若「纯向量 + 高质量分块」在 80% 问题上已够用，是否要为一小撮复杂推理上整图？
- 建议：**分层体验**——简单问走快速通道（向量+关键词），复杂/多跳/全局问走图谱通道，并在产品上明确区分（如「深度分析」按钮）。

**对落地的要求**：
- 上线前必须有**可量化的体验基线**（如：100 个真实问题集 + 人工标注），否则不批准大规模铺开。
- 运维与业务要有一致的「健康仪表盘」：今日问答量、平均延迟、低置信度占比、人工纠正率。

---

### 2.2 马斯克视角（第一性原理与规模）

**核心主张**：
- 「不要从‘别人怎么做的’出发，从‘物理上必须发生什么’出发。」
- 物理上必须发生的事：海量文档 → 被切块/标注 → 变成可检索的结构（向量+图）→ 查询时在有限时间内命中相关证据 → 生成可追溯的答案。任何不能缩短这条链或不能规模化的设计都应质疑。
- **增量与成本**：全量重建图在电网级文档量下不可接受。必须设计「文档/块级指纹 + 增量更新」，新文档只算新部分，旧文档变更只算变更块。
- **垂直整合**：解析、分块、抽实体关系、建图、检索、生成，若由多家供应商拼装，问题定位会变成噩梦。倾向**单一技术栈内闭环**或**明确边界的少数几个栈**，每层有清晰 SLA。

**对技术选型的立场**：
- 图谱的价值在于：多跳推理、实体消歧、全局摘要。若验证下来这些只占 10% 的查询但占 50% 的成本，应**按需上图**（例如只对「规程/制度/事故案例」建图，对一般通知/公示只做向量）。
- 存储：图库与向量库必须能水平扩展，且与现有电网数据中台/湖仓的权限与审计体系打通，避免又建一座「知识孤岛」。

**对落地的要求**：
- 第一期就要有**真实文档量与真实 QPS** 的压测数据（例如 100 万文档、50 QPS 持续 1 小时），否则规模假设是猜的。
- 明确「最小可行图谱」：先覆盖 1–2 个业务域（如安规、设备台账），验证效果与成本再推广。

---

### 2.3 专家团队视角（架构、安全、合规、运营）

**架构组**：
- 国家电网级必然**多机房/多域**：生产、管理信息大区、互联网大区隔离。文档解析与图谱构建建议放在**管理信息大区**，问答服务可部署在需接入的一侧，通过安全边界与审计网关交互。
- 组件建议：解析与任务调度无状态、可水平扩展；图库与向量库支持主从/分片；检索与生成服务分离，便于独立扩容与限流。
- 与现有体系对齐：若已有数据中台、数据目录、主数据，知识图谱应作为「知识层」与目录/主数据做实体关联，避免重复建设。

**安全与合规组**：
- **等保**：系统定级需在规划设计阶段完成（二级及以上需专家评审）。知识图谱与问答系统通常定为**三级**（涉及大量业务与部分管理数据），每年测评、每年汇报。
- **关基**：电力属关键信息基础设施。须落实：专门安全管理机构、年度风险评估、重大事件报告；数据完整性、保密性、可用性；采购产品优先安全可信，必要时通过网络安全审查。
- **信创**：服务器、操作系统、数据库、中间件、关键应用组件优先信创目录；LLM 与嵌入模型优先国产或境内可控；若用开源组件（如 RagFlow、Neo4j），需有**供应链安全评估**与漏洞管理流程。
- **数据安全**：文档与图谱数据分类分级；访问与导出审计；脱敏与权限按角色/部门最小化。

**业务与运营组**：
- 电力行业已有实践：调度知识图谱、设备运检图谱、客服智能问答（如 ChatPower）；标准 T/CES 102-2022 知识图谱组件功能及接口规范。
- 建议与**业务域**对齐：先选 1–2 个高价值域（如安规、两票、设备缺陷/故障案例），与业务方共建「问题集 + 标准答案」，用于效果评估与持续优化。
- 运营指标：构建延迟（从文档上传到可问）、索引覆盖率、问答准确率/满意率、人工纠正与反馈闭环。

## 三、第二轮讨论：冲突、权衡与共识

### 3.1 冲突点一：图谱的边界

- **乔布斯**：担心「为了图而图」导致体验复杂、延迟高；坚持按查询类型分流，简单问不走图。
- **马斯克**：同意按需上图，但要求有数据支撑——需要 A/B 或分层统计（简单问 vs 复杂问占比、上图对准确率与延迟的实际影响）。
- **专家**：从合规与可解释性看，图谱有利于「答案可追溯到条文/设备/事故」，适合安规、制度类；建议**按业务域**划分：安规/两票/制度用图+向量，一般通知/公示仅向量。

**共识**：采用**分层检索策略**——默认向量+关键词；对特定业务域或检测到的「多实体/多跳/全局」问法，再走图谱增强；图谱范围先限定在 1–2 个核心业务域，再逐步扩展。

---

### 3.2 冲突点二：开源 vs 信创与供应链

- **马斯克**：倾向用经过验证的开源（如 RagFlow、LightRAG、Neo4j）快速迭代，避免从零造轮子。
- **安全合规**：开源组件必须纳入**供应链安全管理**：版本固定、漏洞跟踪、必要时替换为信创等价产品或加固版本；涉及关基的采购需满足审查要求。
- **专家**：折中方案——**核心能力分层**：文档解析、任务调度、检索与生成可基于开源或国产商业产品；图数据库与向量库在信创目录内优先选型（如国产图库、国产向量库）；LLM/嵌入模型优先国产或境内可控，并具备离线/专有化部署能力。

**共识**：技术选型遵循「**信创优先、开源可审、可替换**」：关键组件有信创或国产替代路径；使用开源时需做安全评估与版本锁定，并预留替换接口。

---

### 3.3 冲突点三：一期范围与上线标准

- **乔布斯**：一期必须有清晰体验基线（100+ 真实问题、准确率/延迟目标），否则不批准全量推广。
- **马斯克**：一期用真实文档量与 QPS 压测验证架构，范围可限定在 1 个业务域 + 单地域，但**数据与流量要真实**。
- **专家**：与等保、关基节奏一致：一期完成定级备案与基本安全建设，满足等保三级基本要求；业务上完成 1–2 个业务域上线与基线评估。

**共识**：一期范围 = **单业务域（如安规）+ 单地域/单机房 + 真实文档量（如百万级页）+ 真实问题集基线**；上线门禁 = 基线准确率/延迟达标 + 等保测评通过 + 压测通过。

## 四、第三轮讨论：方案收敛与原则锁定

### 4.1 统一原则（经三轮后锁定）

1. **体验可度量**：上线前建立「问题集 + 标准答案」基线，持续跟踪准确率、首答满意率、P99 延迟、可解释性。
2. **规模可验证**：用真实文档量与目标 QPS 做压测与成本测算；增量更新为必选能力，禁止全量重建图作为常规手段。
3. **图谱按需**：分层检索（向量+关键词为主，图谱增强为辅）；图谱先覆盖 1–2 个高价值业务域，再按数据扩展。
4. **合规先行**：等保定级与建设同步，关基要求（专责机构、年度风险评估、事件报告）落地；信创优先，开源可审、可替换。
5. **可运营**：健康仪表盘、人工反馈闭环、构建延迟与覆盖率监控；与数据中台/主数据对接，避免知识孤岛。

### 4.2 技术栈共识

- **文档解析与调度**：支持百万级文档、多格式（PDF/Word/Excel/网页等）、深度解析（表格/多模态）；任务分布式、可水平扩展；与现有存储与权限对接。
- **图谱构建**：实体与关系抽取可基于 LLM（国产/境内可控）；图存储支持水平扩展与增量；优先选用支持「文档/块级指纹」的流水线（如 LightRAG 思路或自研增量策略）。
- **检索**：向量 + 关键词混合；对选定业务域启用图谱增强（多跳/实体消歧/社区摘要）；检索结果可追溯到原文与条款。
- **生成与可解释性**：答案带引用与来源；低置信度时降级或转人工；审计日志完整。
- **基础设施**：部署在管理信息大区；图库/向量库/LLM 均可国产化或信创替代；支持主从/分片与限流、熔断。

### 4.3 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 文档量与延迟导致构建滞后 | 增量更新 + 优先级队列（核心制度/安规优先）+ 资源弹性扩展 |
| 图谱质量差导致答非所问 | 业务域限定 + 问题集基线 + 人工抽检与反馈闭环 |
| 信创组件性能或生态不足 | 关键路径压测 + 预留商用/开源替代方案与接口 |
| 等保/关基不合规 | 规划设计阶段定级与方案评审，安全与合规组全程参与 |

### 5.2 分阶段实施路径

| 阶段 | 目标 | 范围 | 交付物 | 周期（参考） |
|------|------|------|--------|----------------|
| **Phase 0** | 定级、选型、基线 | 无生产流量 | 等保定级与备案；技术选型报告（信创/开源清单）；100+ 问题集与基线指标；POC 环境 | 2–3 月 |
| **Phase 1** | 单域上线、验证规模与体验 | 1 个业务域（如安规）、单地域、百万级文档 | 可用的解析→图谱→向量→问答流水线；基线准确率/延迟达标；压测报告；等保测评通过 | 4–6 月 |
| **Phase 2** | 多域扩展与增量运营 | 2–3 个业务域、增量更新、多地域可选 | 增量更新上线；多域检索与路由；运营仪表盘与反馈闭环 | 3–4 月 |
| **Phase 3** | 全网推广与持续治理 | 全业务域、与数据中台/主数据深度对接 | 知识治理流程；与目录/主数据实体关联；持续优化与合规复测 | 持续 |

### 5.3 技术选型建议（国家电网级）

- **文档解析与任务调度**  
  - 优先：**RagFlow**（深度文档理解、分布式任务、多格式）或具备同等能力的**国产/信创产品**。  
  - 要求：支持优先级队列、增量触发、与现有存储与权限对接；满足等保对日志与访问控制的要求。

- **图谱构建与存储**  
  - 构建：采用**增量友好**的流水线（如 LightRAG 式实体/关系抽取 + 图 union，或自研文档/块级指纹）。  
  - 存储：**信创图数据库**优先（满足等保与关基采购要求）；若短期采用 Neo4j，需做供应链评估并规划国产替代路径。  
  - 范围：一期仅对选定业务域（如安规、两票）建图，其余域仅向量+关键词。

- **向量检索与模型**  
  - 向量库：**信创/国产向量库**优先，支持百万~千万级、混合检索与权限过滤。  
  - 嵌入模型：**国产或境内可控**，可专有化部署；与现有身份与权限体系集成。  
  - LLM：**国产或境内可控**，支持私有化；用于抽取与生成的模型需统一审计与版本管理。

- **检索与生成服务**  
  - 策略：默认**向量 + 关键词**；对配置的业务域或检测到的复杂问法启用**图谱增强**（多跳/实体/社区摘要）。  
  - 必须：引用溯源、低置信度处理、限流与熔断；日志满足等保与关基审计。

- **部署与高可用**  
  - 部署在**管理信息大区**，通过安全边界向接入侧提供 API；解析与构建无状态可扩展；图库/向量库主从或分片；年度演练 RTO/RPO。

### 5.4 合规与运营检查清单

- **等保**：定级与备案完成；二级及以上专家评审；三级每年测评与汇报；制度与记录完整。  
- **关基**：专责安全管理机构；年度风险评估与重大事件报告；数据完整性/保密性/可用性措施落地。  
- **信创**：关键组件信创清单与替代路径；开源组件版本锁定与漏洞管理。  
- **运营**：问题集基线与准确率/延迟监控；人工反馈与纠正闭环；构建延迟与覆盖率；与数据中台/主数据对接计划。

## 六、总结

经三轮「最强大脑」式讨论，形成以下结论：

1. **体验与规模都要用数据说话**：基线问题集、压测与增量能力是上线门禁。  
2. **图谱是增强手段**：分层检索、按业务域上图、先 1–2 域验证再扩展。  
3. **国家电网级必须合规先行**：等保、关基、信创与供应链安全纳入设计，而非事后补课。  
4. **落地路径清晰**：Phase 0 定级与基线 → Phase 1 单域验证 → Phase 2 多域与增量 → Phase 3 全网与治理。

本方案可直接作为国家电网级「文档→知识图谱→智能问答」项目的顶层设计输入，并与既有信息化、数据中台及电力行业标准（如 T/CES 102-2022）对齐使用。
