# 全产品 UI/UX 重设计：最强大脑 × 乔布斯 × 专家团队 10 轮研讨

> 目标：对产品内**全部页面/视图**做 UI/UX 重设计，先发散后收敛，产出**每页独立设计方案**。  
> 参与角色：最强大脑（战略/系统）、乔布斯（极简/焦点）、产品、UX、视觉、前端架构、无障碍。

# 第一轮（发散）：问题与目标

**最强大脑**  
- 产品本质是「想法 → 画布 → 节点四维（View/Spec/Impl/Test）」的**单源真相**系统，但当前 UI 没有强烈传达「一个节点 = 四维一体」；用户容易把画布当流程图、把详情当普通表单。  
- 目标：每个页面都要回答「用户此刻在做什么、下一步最少可选动作是什么」。

**乔布斯**  
- 若一个界面需要解释才能用，就失败了。首屏应 3 秒内让人懂：这是「用自然语言/文件生成产品结构并编辑」的工具。  
- 目标：砍掉一切与「生成/编辑/预览」无关的装饰与重复入口。

**产品**  
- 画布、详情、对话、蓝图、演示、风格——六个主场景，入口分散（顶栏、画布上按钮、节点双击、轨、弹窗），心智负担大。  
- 目标：收敛为「画布 + 节点详情 + 对话」主三角，蓝图/演示/风格为明确次级入口。

**UX**  
- 新用户不知道「先输入什么、在哪输入、生成后去哪看」；空画布没有强引导。  
- 目标：每页都有明确「主行动」与「空状态即邀请」。

**第一轮小结**  
- 共识：重设计要**强化「画布为源、节点四维一体」**，**每页一个主任务、最少必要操作**，**空状态即引导**。  
- 分歧保留：是否保留项目蓝图为一级入口、演示/风格是否折叠进节点详情内。

# 第二轮（发散）：用户旅程与触点

**最强大脑**  
- 主旅程：**进入 → 输入想法/文件 → 看到画布变化 → 点节点进入详情 → 编辑某一维 → 预览/演示**。每个触点对应一个或一组页面；重设计要保证触点间**无断点、无歧义**。

**UX**  
- 进入：加载态（P8）→ 首页（P1）→ 画布（P2）。若首屏只有顶栏+空白画布，用户会愣；画布上应有**唯一明显输入入口**（当前输入在右侧面板，发现性弱）。  
- 输入后：结果应在画布（P2）可见，并在对话（P4）有反馈；澄清时 P4 自动展开。  
- 编辑：双击节点 → P3 全屏；P3 内应有「返回画布」的稳定出口。

**产品**  
- 次要旅程：导出/保存（顶栏）、打开蓝图（顶栏）、演示（画布上按钮）、风格（演示内或全局）。这些入口可收敛到顶栏或画布上一处「更多」菜单，避免散落。

**前端架构**  
- 当前 P2/P3/P4 通过 store 与 URL 无强绑定，不利于「分享某节点」「书签详情」。后续若做分享，需考虑路由与视图对应。

**第二轮小结**  
- 主旅程明确：加载 → 画布（含输入入口）→ 生成 → 对话反馈/澄清 → 节点详情编辑 → 预览/演示。  
- 每页在旅程中的位置与前后跳转要在分页方案里写清。

# 第三轮（发散）：各专家对现状的批评

**乔布斯**  
- P1 顶栏：按钮过多（新建/保存/打开/添加节点/蓝图/导出/更多），像工具栏合集，没有层级。  
- P2 画布：空状态两行字，没有「在这里输入」的张力；右上「演示」「UI 风格选择」「⋯」分散。  
- P3 节点详情：左侧树+右侧预览+底部条，信息密度高，但「四维」用 Tab 切换，存在感弱。  
- P4 对话：轨与面板逻辑已收敛，但输入区在面板底部，画布上无任何「从这里开始」的暗示。  
- P5 蓝图：Tab 多、表单长，像后台配置页，不像产品 IDE 的一部分。  
- P6/P7：功能强但入口深，新用户难发现。

**视觉**  
- 全局深色+青色，与多数 AI 产品雷同；画布背景、节点卡片、详情层缺少「产品/文档」的辨识度。  
- 缺少统一的间距与字阶系统，部分区域拥挤、部分空洞。

**无障碍**  
- 画布节点、Tab、对话消息的焦点顺序与 landmark 需统一；加载态、错误态需同时提供非视觉反馈（aria-live、角色）。

**第三轮小结**  
- 共性问题：入口多且平、空状态弱、视觉同质化、信息层级不足。  
- 分页问题：见上；收敛阶段需逐页给出对策。

# 第四轮（发散）：可能方向与形态

**最强大脑**  
- 方向 A：**画布即首页**。顶栏极简（Logo + 项目名 + 一个「更多」），输入以画布中央或底部一条「命令线」为主，对话为从属。  
- 方向 B：**双模式切换**。明确「浏览模式」（画布+轨）与「编辑模式」（全屏详情），用顶部或边缘 Tab 切换，避免同屏堆叠。  
- 方向 C：**节点为中心**。进入后默认聚焦「当前节点」或「未选」，所有操作都围绕「当前节点」或「新建」，顶栏只保留保存/导出/设置级。

**乔布斯**  
- 倾向 A + 命令线：一个输入框（在画布下方或中央占位）即主入口，其余收起来。对话是输入的结果展示区，不是并行的「聊天」。

**UX**  
- 空画布应有一个**大占位输入区**（类似 Spotlight），而不是让用户先找右侧轨再展开再输入。可考虑：画布中央首次显示「描述产品想法或拖入文件」，点击/聚焦后展开为输入条或跳转到对话面板并聚焦输入。

**产品**  
- 蓝图可降级为「项目设置」子流，从顶栏「更多」进入；演示与风格保留为画布上显性按钮（高频），但样式与主行动区分。

**第四轮小结**  
- 三个方向均保留；收敛时选主方向（建议 A：画布即首页 + 一条主输入），其余作为分页细节（如 P2 空状态用大占位输入，P4 为输入结果与澄清区）。

# 第五轮（发散）：边界与极端情况

**最强大脑**  
- 无节点、单节点、多节点、超大图（100+ 节点）下，画布与详情性能与可读性不同；空状态、单节点状态应有专门设计，避免与多节点共用同一套布局。  
- 澄清时若用户不回复就关面板，需有「待澄清」的持久提示（如轨上红点），而不是静默丢失。

**UX**  
- 长对话、多轮澄清、生成失败：P4 需有「错误态」「重试」「清空对话」的明确出口。  
- 节点详情内多 Tab、长表单：P3 需考虑 Tab 过多时的折叠或分组（如「文档」与「实现」分组）。

**前端架构**  
- 演示模式（P6）与画布/详情共享 store，若用户从演示切回画布，状态一致性需保证；路由或模式切换要有清晰边界。

**第五轮小结**  
- 边界纳入分页方案：P2 区分空/单/多节点；P4 区分正常/澄清中/错误；P3 考虑 Tab 分组与默认 Tab；P8 考虑超时与错误态。

---

# 第六轮（收敛）：统一原则

**最强大脑**  
- **单源真相可见**：在画布与详情中，用户应能感知「一个节点 = View/Spec/Impl/Test 四维」；可在节点卡片或详情标题区用轻量标识（如四格 icon）强化。  
- **主旅程无断点**：输入 → 画布更新 → 对话反馈 → 详情编辑，每步都有明确反馈与下一步建议。

**乔布斯**  
- **一个主行动**：每个页面只突出一个主按钮或主输入；其余收纳进「更多」或次级。  
- **零解释**：通过布局与文案（含 placeholder）让人 3 秒内理解「能做什么、先做什么」。

**产品**  
- **主三角**：画布（P2）、节点详情（P3）、对话（P4）为主；首页（P1）为容器；蓝图（P5）、演示（P6）、风格（P7）为次级，入口收敛。  
- **空状态即邀请**：P2 空画布、P4 无消息、P5 未填画像，都用一句行动句 + 占位示例，而非纯说明。

**UX**  
- **一致的空间语言**：主内容区、侧边/轨、弹层、Toast 的 z-index 与动效统一；焦点与 landmark 可预测。

**第六轮小结**  
- 原则锁定：单源真相可见、主旅程无断点、每页一个主行动、零解释、主三角+次级收敛、空状态即邀请、一致空间语言。  
- 以下分页方案均依此原则展开。

---

# 第七轮（收敛）：分页优先级与依赖

**产品**  
- 优先级：P1/P2/P4（主流程）> P3（编辑）> P8（加载）> P5（蓝图）> P6/P7（演示与风格）> P9（开发页）。  
- 依赖：P2 依赖 P1 布局；P3 与 P2 切换；P4 与 P2 联动（轨+面板）；P5/P6/P7 为覆盖层，依赖当前画布/节点状态。

**乔布斯**  
- 先做 P1/P2/P4 的「主行动 + 空状态」，再做 P3 的「四维感」与简化 Tab；P5 可先收进「更多」并简化 Tab 数量。

**第七轮小结**  
- 实施顺序：P1 容器与顶栏收敛 → P2 画布与空状态 → P4 对话与输入 → P3 节点详情 → P8 → P5 → P6/P7 → P9。

# 第八轮（收敛）：各页面独立设计方案

## P1 首页容器

- **目标**：承载顶栏 + 画布区 + 加载态 + 首屏提示；不抢主内容焦点。  
- **布局**：顶栏固定高度、单行；主区 flex 占满，内为 InfiniteCanvas（画布+轨/面板+详情）；无底部栏。  
- **顶栏收敛**：左侧「项目名」或 Logo；右侧「保存」「导出」+ 一个「更多」（新建/打开/蓝图/设置等），主行动不超过 3 个可见。  
- **加载态（P8 合一）**：见 P8。  
- **首屏提示**：保留「已就绪」短 Toast，可考虑改为画布内轻量横幅（如「在右侧打开对话开始」）一次展示，避免与对话轨重复。

---

## P2 画布主视图

- **目标**：无限画布为主，空状态强引导，多节点时节点卡片与连线清晰、可双击进详情。  
- **主行动**：未选节点时，**主行动 = 输入想法**；输入入口在**右侧对话轨展开后的面板底部**，画布上通过**空状态文案 + 右侧轨图标**引导「打开对话开始」。  
- **空状态**：无节点时，画布中央区域显示一句主文案（如「用一句话描述产品，或拖入文件」）+ 副文案（如「打开右侧 AI 对话开始」）；可配轻量插图或图标，不喧宾夺主。  
- **有节点时**：保持 ReactFlow 画布；节点卡片上可增加「四维」轻量标识（如四格点）；右上保留「演示」「风格」入口，其余收进「⋯」。  
- **与 P4 联动**：轨 48px 默认；展开后 380px 面板含对话历史 + 建图输入；澄清时自动展开并高亮选项。

---

## P3 节点详情视图

- **目标**：全屏编辑当前节点，四维（View/Spec/Impl/Test）清晰，预览与表单平衡。  
- **布局**：全宽；顶部条（返回 + 节点标题 + 可选保存）；主体为**左侧结构（树/列表）+ 右侧预览 + 底部输入条**；Tab 区与预览区视觉分离。  
- **主行动**：当前上下文的主行动 = 「生成/更新 UI」或「从 Spec 生成」等，底部 CommandBar 突出一个主按钮，其余为附件/说明。  
- **四维呈现**：Tab 命名为 View / Spec / Impl / Test，或分组为「界面与文档」「实现与测试」；默认打开 View 或上次使用的 Tab。  
- **返回**：顶部明确「返回画布」或箭头，一键关闭详情回到 P2。

---

## P4 对话与输入

- **目标**：对话为画布服务；历史可回溯，澄清内联，输入唯一且明显。  
- **布局**：窄轨 48px（默认）+ 展开 380px；展开后顶部标题 + 收起，中部滚动对话列表，底部建图输入（附件+输入框+发送）。  
- **主行动**：展开后面板内**主行动 = 底部输入框**；placeholder 为「描述产品想法，或拖拽文件到这里」。  
- **澄清**：追问与选项在对话流内联；等待澄清时输入区禁用并提示「请在上方选择或输入后发送」；收到澄清请求时自动展开面板。  
- **空状态**：无消息时展示一句引导 + 「加载示例对话」可选；不堆砌说明。

---

## P5 项目蓝图

- **目标**：集中管理项目画像、业务/交互/数据/拓扑/规则/事件/用户故事，作为生成与导出的上下文。  
- **入口**：顶栏「更多」内「项目蓝图」，不占主栏。  
- **布局**：弹层或侧拉抽屉；顶部 Tab 或分组（如「画像」「业务与交互」「数据与拓扑」「规则与事件」「用户故事」），单列表单或卡片列表，避免多列挤。  
- **主行动**：每个 Tab 内一个主行动（如「保存画像」「添加故事」）；底部「完成」关闭。  
- **与生成联动**：建图时读取画像与规则；在 P4 或 P2 可轻量提示「已使用项目画像」（可选）。

---

## P6 演示模式

- **目标**：全屏演示当前项目节点（如页面流），可切换节点、可打开风格抽屉。  
- **布局**：全屏 iframe 或预览区；顶部或侧边简洁导航（节点列表/上一页下一页）；可选风格抽屉从侧拉出。  
- **主行动**：「播放/切换」为唯一主操作；关闭演示返回画布或详情。  
- **与 P7 关系**：风格选择可在演示内作为「设置风格」入口，不强制独立入口。

---

## P7 风格选择/提取

- **目标**：选择预设风格或从上传/截图提取风格，供生成使用。  
- **入口**：画布右上「风格」或演示内「风格」；不占顶栏主位。  
- **布局**：弹层；风格卡片网格或列表；上传/截图区明确；选定后关闭并可选 Toast「已应用风格」。  
- **主行动**：「应用所选风格」或「从图片提取并应用」。

---

## P8 加载与首屏

- **目标**：Store 未就绪时稳定加载态；首屏一次轻量「已就绪」反馈。  
- **加载态**：全屏居中，旋转或脉冲 + 「加载中」「正在初始化画布」；无多余元素。  
- **超时**：超时后仍进入主界面，可带 Toast「加载完成」或静默；不阻塞。  
- **首屏提示**：保留短时「已就绪」或改为画布空状态内一句「打开右侧 AI 对话开始」；仅首次或会话内一次。

---

## P9 开发测试页（/dev/test-ui）

- **目标**：自检与联调用，非产品主路径。  
- **设计**：单页简洁说明（用途、链接回首页）；可保留简单占位区块用于测试布局/组件，不按主产品视觉规范强求。

---

# 第九轮（收敛）：乔布斯审计

**乔布斯**  
- P1 顶栏收敛、P2 空状态强化、P4 输入唯一且明显、P3 全宽与四维感、P5 收进「更多」——方向正确。  
- 风险：P5 若 Tab 仍过多，会再次变成「配置页」；建议 P5 首屏只露出「项目画像」与「用户故事」两个最常用块，其余折叠或二次展开。  
- 每页「一个主行动」必须落地：P1=无（容器）；P2=「打开对话开始」；P3=「生成/更新 UI」；P4=「输入想法」；P5=「保存」；P6=「播放」；P7=「应用风格」；P8=无。

**最强大脑**  
- 主旅程（输入→画布→对话→详情）已贯穿 P2/P4/P3；单源真相（四维）在 P3 与 P2 节点卡片上可强化，避免只在 Tab 名上存在感弱。

**第九轮小结**
