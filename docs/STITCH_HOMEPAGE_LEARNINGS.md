# Stitch 首页学习笔记（UI + 功能）

> 参考：https://stitch.withgoogle.com 首页与创建流程。用于对标本项目的「创建模式」空状态与入口。

---

## 一、整体布局

| 区域 | 内容 |
|------|------|
| **左侧边栏** | 项目导航与管理（我的项目 / 与我共享、搜索、最近、今年、示例） |
| **主内容区** | 新建入口 + 大输入区 + 示例提示 |
| **顶栏** | Logo + BETA、Docs / 分享 / 设置 / 头像；可放功能横幅（如 New Feature） |

**可借鉴**：创建模式首屏应「左侧列表 + 右侧空白画布/输入」或「全屏输入 + 示例」，避免只有空白画布。

---

## 二、核心 UI 要素

### 1. 新建类型选择

- **文案**：「开始新的」+ 三个选项：**应用** / **Web** / **设计**
- **作用**：先选产出类型，再填描述，减少歧义。

**对标**：我们是否要在「创建」前增加一步：选「产品图 / 单页 / 设计稿」等，再进画布+对话。

### 2. 主输入区

- **占位**：「提出问题并寻找解决方案。」（Propose a problem and find a solution.）
- **视觉**：大输入框、明显边框（如粉/紫）、左侧「+」附件、右下「Ideate」+ 提交箭头
- **心智**：强调「问题 + 解决方案」，而不是「随便说一句」。

**对标**：我们底部输入框可考虑：
- 占位符改为问题/目标导向（如「描述你要做的产品或解决的问题」）；
- 主按钮文案从「发送」改为「生成产品图」或「Ideate」类动词。

### 3. 示例提示（Try these prompts）

- **位置**：输入区下方
- **内容**：2 条完整、可点击的示例，例如：
  - 商品目录页（季节筛选、极简网格、浅橙主题）
  - F1 车手资料页（pastel red 主色）
- **作用**：降低冷启动成本，示范「多具体才能出好结果」。

**对标**：我们创建模式空状态已有「打开 AI 对话」CTA，可增加：
- 「试试这些描述」：健身 App、电商首页、审批流程等 2～3 条，点击即填入输入框或直接触发生成。

## 三、功能逻辑（与我们的差异）

| 维度 | Stitch | 我们（当前） |
|------|--------|--------------|
| **入口** | 先选类型（应用/Web/设计）→ 再输入问题 → Ideate | 直接进画布，底部输入描述 → 生成图 |
| **预期输入** | 问题陈述 + 解决方案探索（偏详细） | 一句需求也可（已改为默认不挡） |
| **示例** | 明确给出「试试这些提示」并可点击 | 可补充示例提示块 |
| **项目结构** | 左侧「最近 / 今年 / 示例」列表 | 我们有画布+节点，缺「项目列表」入口时的一致性 |

**可借鉴**：
1. **示例块**：在空状态或输入区下方增加「试试：健身软件 / 电商首页 / 报销审批」等，点击即带出 prompt 或直接发起生成。
2. **占位与按钮**：占位符和主按钮文案向「提出问题 / 寻找方案」或「描述产品目标」靠拢，与 Stitch 心智对齐。
3. **类型选择（可选）**：若后续支持「只生成单页」「只出设计稿」，可像 Stitch 一样在创建前增加「应用 / Web / 设计」类选择。

## 四、可直接落地的改进建议

1. **创建模式空状态**  
   - 保留「打开 AI 对话」主 CTA。  
   - 增加一句副文案，如：「描述你要做的产品或要解决的问题，AI 会生成产品结构图。」  
   - 下方增加 **「试试这些描述」**：2～3 条可点击示例（如「做一个健身 App，包含训练计划、打卡、数据统计」「做一个商品列表页，支持按分类筛选」），点击后填入输入框或直接触发生成。

2. **输入区**  
   - 占位符：改为问题/目标导向（例如「描述产品想法或要解决的问题…」）。  
   - 主按钮：保持「发送」或改为「生成产品图」等，与 Stitch 的「Ideate」语义接近。

3. **不改变现有逻辑**  
   - 仍为「默认不挡、直接尝试生成」；示例与文案只做引导，不增加前置门槛。
