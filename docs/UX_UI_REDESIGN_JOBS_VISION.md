# AI-Native IDE：乔布斯式 UX/UI 重塑方案

> **定位**：不是「多一个功能」，而是 **让用户觉得产品懂自己、且从不挡路**。  
> 以下方案以 **Steve Jobs 式产品观**（极简、工艺、情感、一条主故事线）重写体验叙事，并与当前实现（画布 + 节点 + UI/需求/实现/测试 + AI 对话）对齐。

---

## 一、三条不可妥协的原则

### 1. 人们不知道自己要什么，直到你把它摆到面前

- **主路径必须自解释**：从打开产品到「看见可点的页面」，步骤 ≤3，且每一步都有**可见的下一步**（不是说明书，是界面上的光、位置、动效）。
- **AI 是魔术师的手**，不是第二套菜单：对话区只做「补意图、消歧、加速」，不把用户从画布拽走。

### 2. 简单比复杂更难——你必须下狠心砍

- **同一时刻只有一个「主角」**：画布 **或** 节点详情 **或** 蓝图——层级要硬规则，禁止三块同时抢注意力。
- **设置与档位**（模型、视口、风格预设）收进**一处**或**上下文内嵌**，避免工具栏无限膨胀。

### 3. 工艺在细节里——用户会感受到，但说不清

- **反馈有材质**：成功不是绿块，是「松了一口气」的轻确认；错误不是红字堆砌，是「我知道哪一步错了 + 怎么修」。
- **动效只表达状态**：进入、完成、失败各一种曲线，禁止装饰性弹跳。

---

## 二、用户真正要完成的一件事（第一性原理）

**一句话**：把脑子里的产品，变成 **可看的界面 + 可交的需求 + 可落地的实现与测试**，且全程可改、可回溯。

**推论**：

| 阶段       | 用户心理     | 界面应回答的问题     |
|------------|--------------|----------------------|
| 空白画布   | 我从哪开始？ | 「说一句话或贴一张图」|
| 有节点     | 这页是什么？ | 点进去 → UI 立刻可见 |
| 改需求     | AI 懂我吗？  | Tab 即意图（UI/需求/实现/测试）|
| 出错       | 谁的问题？   | 人可修 / 可重试 / 可降级 |

---

## 三、当前体验断层（诚实清单）

1. **反馈层杂乱**：Toast 曾混用 emoji、时长、位置不一，**没有统一「产品声音」**。
2. **认知负荷**：画布工具、节点编辑、AI 对话、蓝图——**并行入口多**，新用户不知道「现在该看哪」。
3. **错误即放弃**：部分失败路径只给文案，**没有「下一步按钮」**（重试、换模型、缩小输入）。
4. **视觉方言不统一**：深色画布 + 多种卡片密度 + 系统感 Toast = **不像同一款产品**。

---

## 四、重塑方案（可执行）

### 4.1 信息架构：一条脊骨 + 两侧外挂

```
        [ 蓝图 / 项目画像 ]（少打扰，按需）
                    │
    ┌───────────────┴───────────────┐
    │     无限画布 = 主舞台          │
    │  节点 = 页面，边 = 关系        │
    └───────────────┬───────────────┘
                    │
        [ 节点详情：UI → 需求 → 实现 → 测试 ]
                    │
        [ 右侧 AI 对话 = 与当前上下文绑定的共犯 ]
```

- **规则**：打开节点详情时，**画布退为上下文**（可轻微压暗或缩略），主舞台让给「当前页」。
- **规则**：AI 输入框的 placeholder / 前缀 **必须随 Tab 变**，让用户感到「我说的话被正确分类」。

### 4.2 反馈系统规范（Toast / 轻提示）

| 类型   | 标题语气     | 副文案要求        | 时长建议 |
|--------|--------------|-------------------|----------|
| success | 短、完成态   | 可选：下一步建议  | 3.5–5s |
| error   | 人话 + 责任  | **必须**：如何修  | 6s+ 或需手动关 |
| info    | 进行中/提示  | 不打断心流        | 3–4s   |
| warning | 可继续但注意 | 后果一句话        | 4–5s   |

**已实现（代码）**：`AppToaster` — 毛玻璃卡片、左侧语义色条、Lucide 图标、右下锚点、与 zinc/cyan 语言一致。后续所有 `toast.*` 应逐步去掉标题里的装饰符号，统一用 **title + description** 分层。

### 4.3 错误即教学（下一步设计）

- **网络 / 429**：Toast 内嵌「稍后重试」或链到 `docs/TROUBLESHOOTING_LLM.md`。
- **生成失败**：对话窗追加一条 assistant 消息，带 **「缩短需求 / 换草稿档 / 仅生成骨架」** 三选一（未来可做 action button）。

### 4.4 视觉与排版语言

- **字阶**：标题 13–14px semibold，说明 12px regular，**禁止**再小一号做正文。
- **圆角**：卡片 16px（`rounded-2xl`），与 Toast 一致，形成家族感。
- **色**：语义色只用于「状态条 + 图标」，大面积仍 zinc，**避免彩虹界面**。

### 4.5 动效宪章

- 进入：200–380ms，`cubic-bezier(0.16, 1, 0.3, 1)`（已有 `--motion-ease-out`）。
- 不出现无意义的循环动画（除 loading）。
- 节点选中：**一次** scale 或 border glow，不要闪。

## 五、分阶段路线图（建议）

| 阶段 | 目标 | 交付物 |
|------|------|--------|
| **P0** | 反馈像「自家产品」 | ✅ 全局 Toast 重设计（AppToaster） |
| **P1** | 主路径不被打断 | 节点详情打开时画布视觉层级；AI 区折叠记忆 |
| **P2** | 错误可恢复 | 失败类 Toast 统一带 action；对话内「修复建议」模板 |
| **P3** |  onboarding | 首次空画布 3 步引导（可关），不写小作文 |
| **P4** | 工艺封顶 | 关键路径 sound/haptic（可选）、导出前「成片感」预览 |

## 六、给设计与实现的检查单

- [ ] 新功能默认能否 **不增加** 常驻工具栏按钮？
- [ ] 用户能否在 **10 秒内** 说出「我现在在改哪一页的哪一类东西」？
- [ ] 任意错误是否都有 **下一步**（不仅是文案）？
- [ ] 同一类组件（卡片、Toast、Dialog）是否 **圆角 / 阴影 / 字阶** 一致？
