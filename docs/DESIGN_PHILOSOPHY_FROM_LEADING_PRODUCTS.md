# 世界级产品 UI 设计理念调研与归纳

> 基于对全球头部科技企业、世界 500 强级产品设计体系及 B2B/SaaS 最佳实践的调研，归纳为**通用设计理念**，并固化为本项目的提示词与约束。不按具体公司或产品名分支，仅吸收共性原则。

---

## 一、调研来源范围

以下类型的设计体系与原则被纳入参考，覆盖消费级、企业级、金融与零售等多行业，以形成泛化结论：

- **系统级设计语言**：Apple HIG、Google Material Design、Microsoft Fluent、IBM Carbon、IBM Design Language
- **500 强 / 大型企业设计系统**：Goldman Sachs GS Design System、ServiceNow Horizon、Walmart Global Tech、REI Cedar、Salesforce Lightning 生态
- **知名产品与设计系统**：Atlassian Design、Airbnb Design System、Stripe Design、Spotify Encore、Facebook/Meta 设计原则
- **B2B / SaaS / 企业软件**：企业仪表盘最佳实践、SaaS UI/UX 指南、B2B 信息架构与导航模式、Power BI / 数据产品设计
- **开源与组件生态**：Radix 可访问性与组合性、Ant Design 企业级一致性、shadcn/ui 与 Vercel 设计观

上述来源覆盖了从消费端到企业端、从操作系统到 SaaS 的数百个产品级 UI 实践；本归纳不枚举具体企业名，而是提炼**跨行业共性**。

## 二、归纳后的通用设计理念（我们自己的表述）

### 1. 内容优先（UI 服务内容，不抢戏）

- 界面存在的目的是承载内容与任务，而非展示装饰。
- 留白、字体、颜色都应服务于**可读性与焦点**；避免与主内容竞争的视觉元素（过重阴影、多主色、无关插图）。
- 每屏应有**单一明确焦点**（主标题或主操作），其余为支撑层级。

### 2. 清晰与视觉层级

- **易读**：正文与标题有明确字号与字重层级；行高与对比度保证可读性。
- **层级清晰**：通过字号、字重、颜色与间距区分主次；用户能在短时间内（如几秒内）理解「这是什么、主要做什么」。
- **结构简单**：信息架构扁平、路径明确；不堆砌无关区块。

### 3. 一致性（同一产品内统一语言）

- 相同类型的元素用相同组件与样式（按钮、卡片、表单、列表）。
- 颜色与圆角、阴影等**设计令牌**统一应用，避免同一页面内多种风格混用。
- 导航、标题、操作区的位置与行为可预期，降低认知负担。

### 4. 留白与节奏（8px 网格与呼吸感）

- 内容区内边距与区块间距遵循稳定网格（如 8px 基准），避免拥挤或随机间距。
- 留白是设计的一部分，用于分隔区块、突出重点，而非「塞满才专业」。
- 数据或列表密集时，仍通过对齐、分组与适度留白保持可扫视性。

### 5. 克制用色与单一主色

- 主操作/CTA 使用**单一主色**（如一种蓝或青），辅以中性灰与少量状态色。
- 避免整页多高饱和色并存；大面积背景以白或浅灰为主，深色仅在用户明确要求时使用。
- 状态与强调用色保持对比度达标，兼顾可访问性。

### 6. 主内容区有实质（禁止空白与占位）

- 主内容区必须与**页面目标**一致：展示数据则有列表/表格/卡片与合理数量的模拟数据；表单则有完整表单项；详情则有完整信息块；仪表盘则有统计与入口。
- 禁止主内容区大面积空白、仅有导航无实质、或仅「示例」「占位」「暂无」类文案。
- 若有侧栏+顶栏，主区须有实际内容，不得为空。

### 7. 组件化与可访问性

- 使用统一组件库（按钮、卡片、输入、导航等）保证一致性与可访问性（焦点、键盘、对比度）。
- 交互元素具备明确状态（hover、focus、disabled），不依赖纯色块无反馈。
- 列表、表单、筛选等模式符合用户对「此类界面」的预期，减少学习成本。

### 8. 数据与仪表盘场景的共性

- **先总览后细节**：关键指标或摘要优先，详情与筛选次之。
- **数据墨水比**：减少无关边框、阴影、装饰，让数据与标签成为主角。
- **3–7 个核心指标**：单屏不堆砌过多图表；主数字+趋势或简要说明优于满屏图表。
- **色彩与图例一致**：同一含义在同一产品内用同一颜色或图例，避免歧义。

## 三、与现有提示词的对应关系

| 归纳理念       | 在本项目中的落点 |
|----------------|------------------|
| 内容优先       | PREMIUM_UI_BRIEF：每屏一个焦点、禁止多色堆砌 |
| 清晰与层级     | UI_CONSTITUTION：字体层级、背景与文本颜色规则 |
| 一致性         | UI_BUILDING_BLOCKS + UI_RECOMMENDED_PATTERNS：必须使用组件与推荐写法 |
| 留白与节奏     | PREMIUM_UI_BRIEF：8px 网格、间距与节奏 |
| 克制用色       | UI_CONSTITUTION：单一主色、白底、状态色 600 级 |
| 主内容区有实质 | HIGH_QUALITY_UI_DEFINITION：与页面目标一致、禁止空白 |
| 组件化与可访问 | UI_BUILDING_BLOCKS + 生成前约束：只用提供组件 |
| 数据/仪表盘    | UI_RECOMMENDED_PATTERNS：StatCard、列表与数据展示结构 |

---

## 四、固化为提示词的原则

- 所有注入到生成链路的文案均使用**通用表述**，不出现「当页面为商品/管理时」等词汇拟合。
- 设计理念以「高质量 UI 的共性」形式写入独立片段（如 `DESIGN_PHILOSOPHY_PRINCIPLES`），在 system prompt 中与 HIGH_QUALITY_UI_DEFINITION、UI_CONSTITUTION 等并列注入。
- 持续迭代时，新原则仍须满足：可跨行业、可操作、不依赖具体产品名或领域词。
