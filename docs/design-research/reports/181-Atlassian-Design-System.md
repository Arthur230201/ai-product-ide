# 181 Atlassian - Atlassian Design System 设计学习报告

## 1. 组织与设计系统名称

- **组织**：Atlassian
- **设计系统名称**：Atlassian Design System
- **官方链接**：https://atlassian.design/

## 2. 设计理念与原则

- **愿景**：成为构建 Atlassian 产品高质量用户界面的基石；使命是让团队能轻松设计、开发并交付高质量的 Atlassian UI。
- **价值观（Values）**：
  - **Foundational**：解决常见问题、提供可依赖的基础；**不为一致而一致**，拒绝无限弹性。
  - **Harmonious**：构建块协同工作，使产品熟悉、统一、像一家人；通过一致性与目的性建立信任。
  - **Empowering, for everyone**：让不同角色、经验与技能的人都能使用系统，扩大影响力。
- **原则（Principles）**：
  1. **Trusted fundamentals before comprehensive patterns**：先做好可靠的基础（可访问性、响应式、企业级标准），提供有主见的构建块，让团队组合出复杂但仍是「Atlassian」的体验；先解决共同基础问题。
  2. **Meet system needs before delivering individual features**：先完成已开始的工作再开新坑；文档、支持、工具与维护是体验的一部分；不只「交付」还要「养好」。
  3. **Bring people on the journey before helping for the moment**：优化自助能力，让团队能独立、自信地做决策；提供恰当的资源与上下文，通过共创建立信任。

## 3. 视觉与基础规范

- **Foundations**：包含 tokens、指南与视觉风格（颜色、间距、字体等）。
- **Components**：可复用构建块，满足具体交互需求并保持一致体验。
- 设计系统由设计、开发与内容设计师共同建设，被内部、市场伙伴与外部用户使用。

## 4. 组件与模式

- **Components**：组合可复用构建块以满足交互需求；强调一致性而非无限灵活。
- **收益**：可扩展、提效、品牌与设计一致、保留设计决策、促进知识共享；文档化避免人员变动导致知识流失。

## 5. 可访问性与包容性

- 原则中明确「accessibility, responsiveness, and enterprise scale」作为质量标准；Empowering for everyone 体现包容性目标。
- 具体 WCAG 或对比度等需在 Foundations / Components 子页查阅。

## 6. 与本项目可借鉴的共性

- **有主见的基础优先于大而全**：先做好可访问、响应式、企业级的基础与组件，再扩展模式；对应我们「生成前必须用提供的组件与推荐写法」。
- **一致性有目的**：Harmonious 强调「目的性」与「信任」，而非为了一致而一致；可归纳为「一致性与清晰目标共同作用」。
- **系统需求优先于单点功能**：文档、支持、维护是体验的一部分；对应我们「只做事前约束、不做事后补救」时，事前约束要完整可执行。
