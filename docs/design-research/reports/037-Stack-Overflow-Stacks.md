# 037 Stack Overflow - Stacks 设计学习报告

## 1. 组织与设计系统名称

- **组织**：Stack Overflow
- **设计系统名称**：Stacks
- **官方链接**：https://stackoverflow.design/

## 2. 设计理念与原则

- **定位**：Stack Overflow 的设计系统，覆盖从品牌到邮件与文案，用于设计、构建与交付 SO 产品线的一致体验。
- **哲学**：围绕「最小化自定义代码」的 CSS/JS 模式库；优先使用既有组件与原子类而非写新 CSS；若设计需要新东西，先判断是否为值得加入库的可复用模式。
- **能力**：可复用组件（按钮、表格、表单等）、可链式原子类构建布局、完整图标集（Stacks-Icons 仓库、SVG）、深色/自定义/高对比主题。

## 3. 视觉与基础规范

- 通过 NPM（@stackoverflow/stacks）或 Unpkg CDN 使用；在 SO 项目内通常预装；MIT 开源，GitHub 活跃维护。

## 4. 组件与模式

- 组件 + 原子类；新需求先考虑是否纳入系统，保证「不重复造轮子」。

## 5. 可访问性与包容性

- 支持高对比模式；具体 WCAG 需在 stackoverflow.design 查阅。

## 6. 与本项目可借鉴的共性

- **最小化自定义**：能用组件与原子类就不写新样式；对应我们「推荐写法 + 既有组件」事前约束，减少模型发明。
- **新需求先问是否可复用**：对应我们「无特例」、将新模式纳入系统而非单页特例。
