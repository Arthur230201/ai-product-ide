# 023 Uber - Base Web 设计学习报告

## 1. 组织与设计系统名称

- **组织**：Uber
- **设计系统名称**：Base Web
- **官方链接**：https://baseweb.design/

## 2. 设计理念与原则

- **定位**：Uber 的开源 React 组件库，实现 Base 设计语言；解决内部大量 Web 应用不一致问题，提供统一设计系统。
- **原则**：可复用组件 + 设计 token（颜色、间距等）→ 一致且可访问的应用；在工程师、设计师与产品之间建立共同语言，提升效率与入职体验。
- **可靠性**：组件在每次提交经视觉回归检测，并用 Puppeteer 做 E2E 测试。
- **可访问性**：为开发者提供构建面向所有访客的可访问产品的工具。
- **定制**：通过「overrides」机制暴露子组件，可定制样式、props 或替换子组件，作为衍生设计系统的「逃生舱」，同时保留 Base 语言。

## 3. 视觉与基础规范

- 设计 token 与 `$theme` 支持主题化；设备无关，便于快速构建 Web 应用。

## 4. 组件与模式

- React 组件 + 工具函数；开源 MIT，GitHub 高星；文档含 versioning policy（v5/v8 等）。

## 5. 可访问性与包容性

- 明确将 accessibility 作为优先；具体 WCAG 需在组件文档查阅。

## 6. 与本项目可借鉴的共性

- **共同语言**：设计系统即工程师/设计/产品的统一语言；对应我们 Constitution + 推荐写法作为生成前唯一约束。
- **Overrides 逃生舱**：在保持基础语言前提下允许定制；对应我们「推荐组件 + 可扩展」而非硬编码死。
- **质量保障**：视觉回归与 E2E；对应我们通过「推荐模式」减少生成结果偏离。
