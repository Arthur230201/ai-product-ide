# 系统设计说明书标准章节目录与先决条件

> 系统设计说明书导出已按下列 14 章 + 附录结构输出；各章所需数据的先决条件、系统是否提供、以及若需提供则在哪里澄清与保存，见下表与后文。

---

## 一、标准章节目录（当前导出结构）

1. **文档总览**  
   1.1 文档目的；1.2 适用范围；1.3 读者对象；1.4 术语与缩写；1.5 参考资料；1.6 文档版本记录。

2. **背景与目标**  
   2.1 业务背景与痛点；2.2 建设目标；2.3 成功指标；2.4 约束条件。

3. **总体架构设计**  
   3.1 系统定位与边界；3.2 架构风格与原则；3.3 总体架构图；3.4 关键技术选型；3.5 核心设计决策（ADR）。

4. **业务与领域设计**  
   4.1 业务流程；4.2 领域模型；4.3 用例/场景；4.4 规则与策略。

5. **功能架构与模块设计**  
   5.1 功能清单与范围（含不做清单）；5.2 模块划分与职责边界；5.3 模块交互关系；5.4 关键页面/接口的业务逻辑说明。

6. **数据架构设计**  
   6.1 数据分类分级；6.2 概念/逻辑/物理模型；6.3 核心表结构说明；6.4 数据一致性策略；6.5 数据生命周期；6.6 数据迁移与初始化；6.7 主数据/字典/编码规范。

7. **接口与集成设计**  
   7.1 接口总览；7.2 API 规范；7.3 关键接口明细；7.4 回调/事件/消息协议；7.5 第三方系统集成；7.6 兼容性与演进策略。

8. **关键非功能设计**  
   8.1 性能与容量；8.2 高可用与容灾；8.3 可扩展性；8.4 可靠性；8.5 安全设计；8.6 合规与隐私；8.7 可维护性；8.8 可观测性；8.9 成本设计。

9. **应用与服务详细设计（按服务/模块展开）**  
   9.x.1 职责与边界；9.x.2 主要接口；9.x.3 核心流程与时序图；9.x.4 数据模型与存储；9.x.5 关键算法/规则/状态机；9.x.6 异常处理与错误码；9.x.7 安全与权限；9.x.8 性能与缓存；9.x.9 配置项与开关；9.x.10 依赖项与风险点。

10. **缓存、搜索与异步化设计（如适用）**  
    10.1 缓存模型；10.2 分布式锁/并发控制；10.3 搜索索引；10.4 消息队列/事件总线。

11. **部署与运维设计**  
    11.1 环境规划；11.2 CI/CD；11.3 配置管理；11.4 运行时依赖；11.5 监控与告警；11.6 运维手册要点。

12. **测试与验收设计**  
    12.1 测试范围与策略；12.2 测试数据与Mock；12.3 性能压测方案；12.4 安全测试；12.5 验收标准与交付物清单。

13. **风险、问题与开放项**  
    13.1 风险清单；13.2 缓解措施与Owner；13.3 已知问题与限制；13.4 开放项与后续规划。

14. **附录**  
    A. 架构图/时序图/ER图清单；B. 错误码总表；C. 配置项总表；D. 接口样例与字段字典；E. 关键决策记录（ADR）。

## 三、是否有必要在系统中提供「所有」内容

- **不必全部在系统内提供**。系统设计说明书中不少内容属于「一次编写、多轮修订」的文档（如详细时序图、错误码总表、配置项总表、ADR 正文），在 IDE 内逐项维护成本高，且与 Confluence/语雀/架构仓库等已有习惯可能重复。
- **建议在系统内提供的**（与画布/项目强一致、导出即可用）：
  - **文档控制**：目的、范围、读者、术语、参考资料、版本记录（便于多轮导出一致）。
  - **背景与目标**：建设目标、成功指标、约束条件（与项目蓝图可复用）。
  - **总体架构**：系统定位与边界、架构风格、技术选型、ADR 列表（核心决策留痕）。
  - **功能与模块**：已支持（从 nodes 自动）；不做清单、模块交互可补充。
  - **数据与接口**：已支持（dbSchema、apiEndpoints 自动）；数据分类/一致性/生命周期、API 规范与集成策略建议有入口。
  - **关键非功能**：性能、高可用、安全、合规、可观测、成本等（评审与交付常查）。
  - **部署与运维**：环境规划、CI/CD、配置管理、监控告警（交付与运维对接）。
  - **风险与开放项**：风险清单、已知问题、开放项（与发布/迭代对齐）。
- **可选在系统内提供的**：业务与领域（可与 PRD 引用）；缓存/搜索/异步；测试与验收；附录 A/B/C/E 的详细内容（可仅占位，导出后在 Word 或外部文档维护）。

## 四、在哪里澄清追问和保存

### 4.1 推荐落点：项目蓝图 + 画布节点（已有 impl）

- **项目蓝图（Project Blueprint）**  
  - 增加 **「系统设计」** 或 **「系统设计说明书」** 区域（可与「全局规则」并列或独立 Tab）。  
  - 字段建议（与 `SystemDesignMeta` 对应）：  
    - **文档总览**：文档目的、适用范围、读者对象、术语与缩写、参考资料、修订记录（表）。  
    - **背景与目标**：业务背景、建设目标、成功指标、约束条件（可复用/引用 projectMeta）。  
    - **总体架构**：系统定位与边界、架构风格与原则、关键技术选型、ADR 列表；架构图可复用现有「拓扑图」或单独上传。  
    - **业务与领域**（可选）：业务流程摘要、领域模型摘要、规则与策略。  
    - **功能与范围**：不做清单（outOfScopeFeatures）。  
    - **数据架构**：数据分类分级、数据一致性策略、数据生命周期、数据迁移方案。  
    - **接口与集成**：接口总览、API 规范、回调/事件协议、第三方集成、兼容与演进策略。  
    - **关键非功能**：性能与容量、高可用、可扩展、可靠、安全、合规与隐私、可观测性、成本设计。  
    - **缓存/搜索/异步**（可选）：缓存模型、消息队列设计。  
    - **部署与运维**：环境规划、CI/CD、配置管理、监控与告警。  
    - **测试与验收**（可选）：测试策略、验收标准。  
    - **风险与开放项**：风险清单、已知问题、开放项与后续规划。  
  - 存储：与 projectMeta / globalRules 一致，持久化到项目 JSON（或单独 `systemDesignMeta`），导出时传入 `exportSystemDesignDoc({ projectMeta, nodes, meta })`。

- **画布节点（已有）**  
  - 各节点 **「实现」** 中已维护 **apiEndpoints**、**dbSchema**；导出时自动填入第 5、6、7、9 章及附录 D。  
  - 若后续需在系统内维护「模块职责与边界」「关键流程说明」等，可扩展 `artifacts.impl`（如 `responsibility?: string`、`keyFlow?: string`）或在节点详情「实现」Tab 增加多行文本，导出时写入对应 9.x 小节。

### 4.2 导出时行为

- 导出系统设计说明书时，从项目读取「系统设计」配置（SystemDesignMeta），填充到对应章节；未配项为「（待填写）」。  
- 第 5、6、7、9 章及附录 D 中与模块/接口/数据相关的内容，继续由画布节点自动生成，无需在蓝图重复填写。

### 4.3 小结

- **当前**：导出已按 14 章 + 附录输出；第 5 章（模块列表与范围）、第 6 章（6.3 核心表结构）、第 7 章（7.3 接口明细）、第 9 章（按模块的接口与数据骨架）、附录 D（接口列表）由系统从 `projectMeta` 与 `nodes` 自动填充；其余章节为占位或通过 `SystemDesignMeta` 预填（接口已留，UI 未上）。  
- **后续**：在项目蓝图中增加「系统设计」配置区，将上表「建议澄清/保存位置」中的字段落地为表单并写入 `SystemDesignMeta`，导出时传入即可补全各章；若需在节点级维护「职责与边界」「关键流程」等，再扩展 `artifacts.impl` 与节点详情面板。
