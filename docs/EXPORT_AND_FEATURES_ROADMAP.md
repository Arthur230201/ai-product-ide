# 导出能力拓展与功能增强路线图

> 当前已支持：PRD（HTML/Word/Markdown）、需求规格说明书、测试报告、系统设计说明书、使用说明书。下文列出**可拓展的导出材料**与**可增加的功能**，供排期与选型参考。

---

## 一、当前导出能力一览

| 导出物 | 格式 | 数据来源 |
|--------|------|----------|
| PRD | HTML / Word / Markdown | projectMeta、globalRules、nodes(spec/view)、拓扑/泳道图、数据字典 |
| 需求规格说明书（SRS） | Word | 同上，企业级版式 |
| 测试报告 | Word（12 章标准） | projectMeta、nodes(test.cases)、TestReportMeta |
| 系统设计说明书 | Word（14 章+附录） | projectMeta、nodes(impl)、SystemDesignMeta |
| 使用说明书 | Word（5 章） | projectMeta、nodes(spec)、UserManualMeta |

---

## 二、可拓展的导出材料

以下均可基于现有画布数据（nodes + projectMeta + 可选 meta）或少量扩展实现。

### 2.1 高价值、数据现成或易得

| 导出物 | 说明 | 数据来源 | 实现难度 |
|--------|------|----------|----------|
| **API 文档 / 接口文档** | 接口列表、所属模块、可选入参/出参占位；或导出为 OpenAPI 3.0 骨架 | `impl.apiEndpoints` 按模块汇总；若需入参/出参可扩展 impl 或 meta | 低 |
| **数据库设计文档 / DDL 汇总** | 按模块汇总 dbSchema，或整理为「可执行 DDL 片段」文档 | `impl.dbSchema` 按节点汇总；可加文档头与命名规范说明 | 低 |
| **需求追踪矩阵（RTM）** | 需求 ↔ 测试用例 ↔ 接口/模块 对应表，便于验收与变更影响分析 | spec.requirements、test.cases、impl 按节点对齐；可输出 Excel/Word 表 | 中 |
| **验收清单 / 交付物清单** | 一页表：模块名、需求条数、用例数、接口数、数据模型有无、验收结论列（空） | 从 nodes 统计 + 表头；交付/UAT 时勾选 | 低 |
| **发布说明 / Release Notes** | 版本 + 更新摘要：本版包含的页面/功能列表（来自节点 title/spec） | projectMeta.version、nodes(spec.title/requirements 摘要) + ReleaseNotesMeta（可选） | 低 |

### 2.2 中等价值、需模板或少量扩展

| 导出物 | 说明 | 数据来源 | 实现难度 |
|--------|------|----------|----------|
| **项目简介 / 一页纸** | 项目名、目标、主要模块、关键指标占位、干系人；用于立项/汇报 | projectMeta + 模块列表 + 一页纸模板（meta 可填目标/指标） | 低 |
| **演示脚本 / Demo Script** | 按节点顺序：页面名称、演示要点、话术占位；用于售前/评审演示 | nodes 顺序（或按边遍历）、spec.title + DemoScriptMeta（每页要点可填） | 中 |
| **培训大纲 / 培训手册** | 与使用说明书类似，但按「学习路径」或角色分章；练习与考核点占位 | spec + 可选「培训 meta」（章节顺序、练习题目） | 中 |
| **运维手册 / Runbook** | 部署、回滚、监控、常见故障与排障步骤；与系统设计 11 章重叠，可做「纯运维」精简版 | 可从 SystemDesignMeta 抽 11 章内容，或独立 RunbookMeta | 低 |
| **安全/隐私评估清单** | 检查项列表（PII、数据流、权限、审计）+ 结论列（空）；模板化 | 固定模板 + 可选项目相关条目（从 spec/impl 关键词生成或 meta 填） | 中 |

### 2.3 需进一步数据或集成

| 导出物 | 说明 | 数据来源 | 实现难度 |
|--------|------|----------|----------|
| **Postman / 接口调试集合** | 可导入 Postman 的 JSON：请求列表（URL、Method 从 apiEndpoints 解析） | 解析 apiEndpoints 得到 method+path；body/headers 占位或默认 | 中 |
| **ER 图 / 数据模型图** | 从 dbSchema 解析表/字段，输出 Mermaid ER 或 PlantUML；嵌入 Word 或单独导出 | 解析 dbSchema 文本（正则或简单解析）；生成 Mermaid/PlantUML | 中高 |
| **产品路线图（Roadmap）** | 按版本/迭代列功能与时间线 | 需节点或模块级「计划版本/迭代」字段，当前无；可先做模板占位 | 中 |
| **竞品/功能对比表** | 我方功能列表（来自 nodes） + 竞品列（空）；用于对标汇报 | nodes 自动填「我方」列；竞品列 meta 或手填 | 低 |

## 三、可增加的功能（非导出物）

### 3.1 导出体验与能力

| 功能 | 说明 | 价值 |
|------|------|------|
| **批量导出 / 一键导出包** | 一次操作导出 PRD + SRS + 测试报告 + 系统设计 + 使用说明书（及可选 API 文档、验收清单）为 zip | 交付/归档时省事，减少漏导 |
| **导出前配置弹窗** | 点击某导出项时，先弹窗填写本次导出用的 meta（如测试报告结论、系统设计范围、使用说明书 FAQ）；可覆盖项目蓝图中的默认值 | 不必为单次导出改蓝图，灵活 |
| **PDF 导出** | 对 PRD、测试报告、系统设计、使用说明书等提供 PDF 选项（基于现有 HTML 或 Word 转 PDF） | 正式评审、归档常要 PDF |
| **导出模板定制** | 支持上传/选择 Word 或 HTML 模板，替换占位符（如 {{projectName}}、{{section:testCases}}）；企业 logo、版式统一 | 满足企业品牌与规范 |
| **多语言导出** | 文档标题、章节名、占位提示等支持英文（或配置语言）；正文仍为画布内容 | 国际化项目、对外交付 |

### 3.2 内容与协作

| 功能 | 说明 | 价值 |
|------|------|------|
| **导出元数据在蓝图中落地** | 在项目蓝图中增加「测试报告」「系统设计」「使用说明书」等 Tab 或区块，表单对应 TestReportMeta / SystemDesignMeta / UserManualMeta，持久化到项目 JSON | 一次配置，多次导出一致；当前 meta 仅接口层支持，UI 未上 |
| **节点级「实现」扩展** | 在 impl 中增加可选字段：接口入参/出参说明、模块职责与边界、关键流程简述；导出系统设计/API 文档时自动带入 | 第 9 章与 API 文档更饱满 |
| **测试用例执行状态** | 在 test 中增加每条用例的执行结果（通过/失败/阻塞/跳过）、执行时间；导出测试报告时自动汇总第 7 章统计 | 测试报告从「空结果」升级为「可填结果」 |
| **版本/快照与对比** | 项目保存为带版本号的快照；导出时可选「按某版本导出」；或对比两版本导出 diff（需求/接口变更列表） | 发布留痕、变更追溯 |
| **评审与审批状态** | 节点或项目级「已评审/已批准」状态；导出时可筛选「仅已批准」或文档中标注审批状态 | 合规与流程管控 |

### 3.3 与外部系统联动

| 功能 | 说明 | 价值 |
|------|------|------|
| **导出到 Confluence / Notion** | 将 PRD 或某文档推送到 Confluence/Notion 指定页面（需 API 与鉴权） | 与现有知识库统一 |
| **导出到 Git 仓库** | 将 Markdown/HTML 导出物按目录结构提交到指定 Git 分支（如 docs/） | 文档即代码、版本可追溯 |
| **与缺陷/需求系统联动** | 从 Jira/禅道等拉取缺陷列表或需求 ID，填入测试报告/RTM；或把「验收清单」同步为工单 | 减少重复录入、双向同步 |

### 3.4 AI 辅助

| 功能 | 说明 | 价值 |
|------|------|------|
| **AI 补充占位内容** | 根据 spec/impl 自动生成：使用说明书 FAQ、API 请求/响应示例、发布说明摘要、演示话术要点 | 减少手写、提高一致性 |
| **从 PRD 生成测试用例** | 已有「从需求生成测试」能力时，可批量生成 test.cases 初稿，再人工润色 | 测试覆盖更全 |
| **从需求生成接口说明** | 根据 spec 与现有 apiEndpoints 生成接口用途与入参/出参描述（自然语言） | API 文档更易读 |

## 四、建议优先级（供排期参考）

### 短期可做（数据现成、收益明确）

1. **API 文档 / 接口文档** 导出（Word 或 OpenAPI 骨架）  
2. **验收清单 / 交付物清单** 导出（一页表）  
3. **发布说明（Release Notes）** 导出  
4. **批量导出 zip**（当前 5 类文档打成一个包）  
5. **项目蓝图中「测试报告 / 系统设计 / 使用说明书」元数据表单**（把现有 meta 落到 UI 并持久化）

### 中期（模板或少量扩展）

6. **需求追踪矩阵（RTM）** 导出  
7. **项目一页纸** 导出  
8. **PDF 导出**（基于现有 Word/HTML）  
9. **导出前配置弹窗**（单次覆盖 meta）  
10. **测试用例执行状态**（节点 test 扩展 + 测试报告第 7 章自动汇总）

### 长期（集成或深度能力）

11. **Postman 集合** 导出  
12. **ER 图 / 数据模型图**（解析 dbSchema → Mermaid/PlantUML）  
13. **导出到 Confluence/Git**  
14. **AI 补充占位内容**（FAQ、发布说明、演示要点等）  
15. **模板定制** 与 **多语言导出**

---

## 五、小结

- **导出材料**：在现有 5 类基础上，可拓展 API 文档、数据库设计/DDL、RTM、验收清单、发布说明、一页纸、演示脚本、培训大纲、运维手册、安全评估清单、Postman 集合、ER 图、Roadmap、竞品对比表等；按数据可得性与价值优先做「API 文档、验收清单、发布说明、批量导出」与「元数据在蓝图落地」。  
- **功能增强**：围绕「导出体验」（批量、PDF、导出前配置、模板、多语言）、「内容与协作」（元数据 UI、节点扩展、执行状态、版本/评审）、「外部联动」（Confluence/Git、缺陷系统）、「AI 辅助」（占位补充、用例/接口说明生成）四类展开，按优先级分短期/中期/长期落地。
