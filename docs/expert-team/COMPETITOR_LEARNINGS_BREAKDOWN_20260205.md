# 竞品可借鉴点详细拆解（2025-02-05）

**目的**：将 v0、Theia Coder、Flexpilot、OpenCode、Jeda、Miro、**Google Stitch** 等与 AI-Native IDE 相关热门项目的可借鉴点做结构化拆解，供超级大脑分析后交内部团队与三方团队讨论，两轮讨论后由乔布斯与马斯克最终裁决。

**流程**：本拆解 → 超级大脑分析 → 内部团队 + 三方团队两轮讨论 → 乔布斯 + 马斯克裁决 → 落地清单。

---

## 一、对标项目与借鉴维度总览

| 项目 | 类型 | 与本站点相关性 | 主要借鉴维度 |
|------|------|----------------|--------------|

| **Theia Coder** | 开源 IDE + 自然语言→完整应用 | 极高：AI 原生 IDE + 应用级生成 | 开源策略、LLM 自由、生成前审查、应用级理解 |
| **Flexpilot IDE** | 开源 AI IDE，自带模型 | 高：多 LLM、隐私优先 | 多模型接入、隐私/本地、VS Code 兼容 |
| **OpenCode** | 终端优先开源 AI 编程助手 | 高：开源、多 LLM、本地 | 终端/IDE 多形态、40+ LLM、社区与星标 |
| **Jeda.ai** | 多模态视觉 + 线框/原型 | 中：画布+多阶段生成 | 多模型协同、线框→可编辑、模板 |
| **Miro AI 产品画布** | 画布 + AI 评估/规划 | 中：画布 + 节点/流程 | 画布 UX、三步规划（现状→方案→人机） |
| **Cursor / Replit / Windsurf** | 主流 AI 编程环境 | 参考：赛道与交互 | 上下文策略、规则/工作流、云端形态 |
| **Google Stitch** | 描述/图像→UI+代码，分钟级 | 极高：生成快且好、设计→开发闭环 | 双模型分轨、UI Constitution、一步出码、Figma+代码、多屏原型 |

## 二、按维度详细拆解（可借鉴点条目化）

### 2.1 产品形态与用户路径（与 PRD→UI、画布入口相关）

| 编号 | 来源 | 可借鉴点 | 具体描述 | 落地可能涉及 |
|------|------|----------|----------|--------------|
| P1 | v0 | 自然语言→组件的一站式心智 | 用户输入描述即得 React 组件，无需「先拓扑再节点再生成」的离散步骤；可对比本站点「想法→拓扑→节点→View/Spec/Impl」是否可收敛为更短路径 | 产品经理、UX、CommandBar/入口 |
| P2 | v0 | 对话式迭代改 UI | 「添加暗黑模式」「使标题固定」等自然语言改 UI，无需改代码；与本站点「节点详情内编辑 + 重新生成」的关系需界定 | NodeDetailPanel、重新生成策略、提示词 |
| P3 | Theia Coder | 「从自然语言生成完整应用」的定位 | 单次生成粒度是「应用」而非单文件；本站点当前是「单节点 View/Spec/Impl」，是否要支持「整项目/多节点一次生成」 | 产品愿景、generate-graph/ui-pipeline 粒度 |
| P4 | Miro | 画布上三步规划（现状→方案→人机） | 用画布做结构化规划而非自由涂鸦；与本站点「画布+节点+边」的语义（节点=页面/功能块）是否可借鉴为「阶段/步骤」的引导 | 画布引导、ProjectBlueprint、空状态 |
| P5 | Cursor/Replit | 主路径入口聚合 | 避免「生成拓扑/生成 UI/生成 PRD」分散在 CommandBar、Toolbar、NodeDetailPanel 等多处；可考虑「主操作台」或「空白画布首屏 CTA」 | 首屏、空状态、InstructionCard |
| P6 | Google Stitch | 双模型分轨（快 vs 好） | Standard 用 Gemini 2.5 Flash 做快速草稿/MVP（TTFT≤120ms），Experimental 用 Pro/ Gemini 3 做复杂与图像输入；简单走快、复杂走好 | ai-config、gateway、按场景选模型 |
| P7 | Google Stitch | 一次出多方案 / 快速切换 | 支持一次生成多套界面变体并快速切换，主观感受「快」；不增加必选步骤 | 生成选项、ViewWorkbench 多方案展示 |
| P8 | Google Stitch | Prototypes 多屏可点击原型 | 多屏拼接成可点击原型、带交互与用户流程，用户感知为「完整应用」而非单页 | 画布节点+边、预览内跳转、流程可点 |

### 2.2 技术架构与管线（与三阶段 UI、LLM、多模型相关）

| 编号 | 来源 | 可借鉴点 | 具体描述 | 落地可能涉及 |
|------|------|----------|----------|--------------|
| T1 | v0 | 针对 Next/React/Tailwind 的专门优化 | 模型或提示对技术栈有显式约束，输出更可预期；本站点已用 Tailwind + 三阶段，可强化「阶段 marker + schema」与 v0 式约束的对照 | ui-pipeline、prompts、DELIVERABLE_QUALITY_GATE |
| T2 | Theia Coder | 透明变更审查（改前可审） | 生成/修改前展示 diff 或摘要，用户确认后再应用；本站点当前多为「生成后即写 View 代码」，是否增加「预览变更→确认→应用」 | NodeDetailPanel、apply 前确认、undo |
| T3 | Theia / Flexpilot / OpenCode | 多 LLM / 自带模型（BYOM） | 支持 OpenAI、Anthropic、Azure、Ollama、自托管等；本站点已有 ai-config/多模型，可对比「接入数量、切换成本、本地优先」策略 | ai-config、gateway、fallback |
| T4 | Flexpilot | 隐私优先与本地部署 | 强调数据不出域、本地模型；与本站点「是否支持完全离线/内网」的路线一致与否 | 部署文档、.env 说明、企业版故事 |
| T5 | OpenCode | 终端 + 桌面 + IDE 多形态 | 同一套能力在不同形态复用；本站点当前以 Web 画布为主，是否预留 CLI/桌面端调用同一套 generate-graph、ui-pipeline | 架构、API 边界、scripts |
| T6 | Jeda.ai | 多模型协同（GPT-4.1 + Claude 等） | 不同阶段或不同任务用不同模型；本站点三阶段可否「结构用 A、美化用 B、交互用 C」并可配置 | ui-pipeline、prompts、config |
| T7 | Google Stitch | 「UI Constitution」固定系统提示 | 颜色、字体、设计原则等写进固定 system prompt，仅当次用户输入/交互为变量；风格一致、可缓存、请求体更短、延迟更低 | prompts、三阶段全局约束、质量门 |
| T8 | Google Stitch | 轻量/重量模型分轨 | Standard=Flash（快），Experimental=Pro/3（好）；本站点可对「快速预览/草稿」与「高质量/复杂输入」分轨选模型 | ai-config、ui-pipeline 按阶段或复杂度选模型 |
| T9 | Google Stitch | 一步出码、无中间格式 | 描述/草图直接生成前端代码，无「先中间格式再转代码」；少一轮调用、少一次解析，端到端更快 | 三阶段可否在部分场景合并或单轮生成（在保证质量前提下） |

## 三、按「采纳难度」与「与现有结论一致性」的初筛

- **与现有结论一致、可直接对齐**：U2、U3（已有多轮 UX 讨论与乔布斯口径）；C4（保留四维，仅需可解释）。
- **需产品/技术决策**：P1、P2、P3、P5、P6、P7、P8（路径与粒度、双模型分轨、多方案、多屏原型）；T2、T5、T6、T7、T8、T9（审查、多形态、多模型分工、UI Constitution、一步出码）；C1、C2、C3、C5、C6（阶段产物、模板、Figma、Prototypes、主题约束）；U4（多方案快感）。
- **偏战略/文档**：E1、E2、E3、U1（叙事、开源、隐私、免费额度）。

**Google Stitch 小结**：快来自双模型分轨（Flash/Pro）、固定 system prompt（UI Constitution）、一步出码与多方案展示；好来自多模态（图+文）、Figma+代码双出口、主题可控、多屏可点击原型。T7/T8、P6、C6 与现有三阶段+质量门可直接对照；P7/U4、C5、T9 需与产品/技术决策一起讨论。
