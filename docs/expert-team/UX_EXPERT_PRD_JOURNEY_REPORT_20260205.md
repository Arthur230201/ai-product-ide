| 成功标准 | 能从想法输入 → 生成/补全节点 → 导出 Full PRD HTML，且 PRD 含每页 UI 设计图、结构完整、可交付 |

## 二、操作路径（真实使用场景）

1. **进入应用**：打开画布与命令栏。
2. **输入需求**：在命令栏输入「我需要做购物软件，包含登录、商品列表、支付三个页面」并触发生成。
3. **生成节点与边（拓扑）**：系统一次生成节点与边（有节点即有拓扑）。
4. **逐步补全**：选中节点，在详情面板中进入 Spec 等 Tab 补全需求；或先生成 UI 再点击「生成需求文档」得到详细页面描述。
5. **导出 PRD**：工具栏「导出 PRD 文档」→「导出 HTML」，获得与项目导出一致的 Full PRD HTML（含每页界面示意）。
6. **验证产物**：导出的 PRD 应含第 5 章功能详述、每页 UI 设计图/界面示意，满足生产级可落地要求。

## 四、用户体验官评估（UX 专家视角）

### 4.1 入口可发现性

- **导出 PRD 入口**：用户需在工具栏找到「导出 PRD 文档」（下载图标+下拉），再选「导出 HTML」。若工具栏入口不明显或与「导出项目」混淆，则标为改进项。
- **建议**：首次使用或空状态时可增加简短引导（如「生成节点后，可在此导出完整 PRD 文档」）。

### 4.2 步骤清晰度

- **从想法到 PRD**：路径为「输入需求 → 生成 → 补全 Spec（可选）→ 导出 PRD」。若用户不知道「先有节点才能导出」，易在空画布时点击导出遇阻。
- **建议**：导出时若节点数为 0，提示「请先生成或添加节点再导出 PRD」，避免静默失败或技术错误。

### 4.3 反馈明确性

- **生成 PRD / 导出中**：应有 loading 或 toast（如「正在生成 PRD 文档…」「Full PRD HTML 导出成功」）。
- **建议**：导出成功后明确提示「已下载 Full PRD HTML，含每页 UI 设计图」，强化生产级可落地认知。

### 4.4 PRD 生产级可落地性

- **必备要素**：PRD 须含项目概述、用户角色与流程、模块详情（含每页 **UI 设计图/界面示意**）、非功能性需求；导出格式与前端「导出 Full PRD HTML」一致。
- **结论**：当前导出产物符合「含每页 UI 设计图」要求，可视为生产级可落地 PRD 的基线满足。 

### 4.5 断点与改进建议

- 若 E2E 未跑或产物缺失：建议先执行 `npx playwright test e2e/prd-product-manager-journey.spec.ts`（需 dev 已启动），再运行本报告脚本。
- 若节点生成依赖真实 LLM：可设置 `AI_RUNTIME=real` 后跑 E2E，以验证真实使用场景下从输入到导出 PRD 的完整路径。
