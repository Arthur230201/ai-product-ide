# 测试报告标准章节目录与先决条件

> 测试报告导出已按下列 12 章结构输出；各章所需数据的先决条件、系统是否提供、以及若需提供则在哪里澄清与保存，见下表与后文。

---

## 一、标准章节目录（当前导出结构）

1. **文档控制信息**  
   标题、项目/系统名称、版本号；编写/评审/批准人、日期；文档修订记录；分发范围与保密级别。

2. **报告摘要（Executive Summary）**  
   测试结论；当前质量风险概览；发布/上线建议与前置条件；关键数据一页化。

3. **背景与目标**  
   测试背景；测试目标；参考依据。

4. **测试范围与对象**  
   测试对象（模块/服务/接口）；版本与构建信息；覆盖范围；不在范围及原因。

5. **测试策略与方法**  
   测试类型；测试方法；准入/准出标准；风险评估与测试重点。

6. **测试环境与配置**  
   环境拓扑；软硬件配置；依赖与外部接口；测试数据策略；环境问题与影响。

7. **测试执行概况**  
   测试周期、人员、执行日历；测试轮次；用例执行统计；需求/故事覆盖率。

8. **缺陷与问题分析**  
   缺陷统计；缺陷趋势；关键缺陷清单；根因分析与改进建议。

9. **质量度量与覆盖度**  
   功能覆盖；代码质量；性能；稳定性；安全（如适用）。

10. **风险、遗留问题与豁免项**  
    已知问题；风险清单；豁免/延期项及批准与补救计划。

11. **结论与发布建议**  
    准出标准对照；上线建议；发布门槛；回滚策略验证。

12. **附录**  
    测试用例/脚本清单；缺陷列表；日志/截图/抓包/监控/性能数据；RTM；术语表。

## 二、各章先决条件与系统支持情况

| 章节 | 先决条件（需哪些数据） | 系统是否已有 | 是否有必要在系统中提供 | 建议澄清/保存位置 |
|------|------------------------|--------------|------------------------|--------------------|
| **1. 文档控制信息** | 项目名、版本、编写/评审/批准人及日期、修订记录、分发范围、保密级别 | 项目名、版本已有（projectMeta）；其余无 | 有必要：便于多轮导出时一致、可追溯 | **项目蓝图** 或 **导出前弹窗**：增加「测试报告元数据」区块（编写人、评审人、批准人、修订记录表、分发范围、保密级别），存到 `TestReportMeta` 或 project 级配置 |
| **2. 报告摘要** | 测试结论、TOP 风险、发布建议、关键数据 | 关键数据可自动：用例总数、覆盖模块数；结论/风险/建议无 | 有必要：报告核心结论 | 同上：测试报告元数据（结论、风险摘要、发布建议）；关键数据由导出时从用例统计自动填 |
| **3. 背景与目标** | 测试背景、目标、参考依据（需求/设计/标准/合同） | 无 | 可选：小团队可 Word 手填 | 若有：项目蓝图「测试报告」或导出配置中的多行文本（背景、目标、参考依据） |
| **4. 测试范围与对象** | 测试对象列表、版本/Build、覆盖范围、Out of Scope | **测试对象**：已有（从节点/模块名自动汇总）；版本/Build、范围、Out of Scope 无 | 对象自动；其余可选 | 对象由导出从 nodes 自动生成；版本/Build、范围、Out of Scope 可在测试报告元数据中增加短文本 |
| **5. 测试策略与方法** | 测试类型、方法、准入/准出、风险重点 | 无 | 可选：多来自测试计划，可 Word 填 | 若需系统预填：测试报告元数据（类型、方法、准入准出、风险要点） |
| **6. 测试环境与配置** | 环境拓扑、软硬件、依赖与 Mock、数据策略、环境问题 | 无 | 可选 | 测试报告元数据或项目级「环境说明」多行文本 |
| **7. 测试执行概况** | 周期、人员、轮次、用例执行统计、覆盖率 | **用例总数、模块数**：已有（自动）；计划/已执行/通过/失败/阻塞/跳过 需执行结果 | 部分有必要：统计需用例级执行结果 | **节点内 test 扩展**：`artifacts.test` 增加可选字段如 `executionStatus?: 'passed'|'failed'|'blocked'|'skipped'|'pending'`、`executedAt?: string`，导出时汇总为「已执行/通过/失败/阻塞/跳过」；周期/人员/轮次可在元数据中填 |
| **8. 缺陷与问题分析** | 缺陷统计、趋势、关键缺陷清单、RCA | 无（多来自 Jira/禅道等） | 不必在系统内建缺陷库；可贴摘要或链接 | 测试报告元数据：支持「关键缺陷摘要」多行文本或「缺陷列表链接」；或导出后 Word 粘贴 |
| **9. 质量度量与覆盖度** | 覆盖率、性能、稳定性、安全等 | 无 | 可选：多来自 CI/监控，非本 IDE 主场景 | 不强制在系统提供；若有需要可加「质量度量摘要」多行文本 |
| **10. 风险与豁免** | 已知问题、风险清单、豁免项及批准/补救 | 无 | 有必要：常与发布决策挂钩 | 测试报告元数据（已知问题、风险与豁免说明） |
| **11. 结论与发布建议** | 准出对照、上线建议、发布门槛、回滚验证 | 无 | 有必要 | 测试报告元数据（上线建议、发布条件、回滚验证说明） |
| **12. 附录** | 用例清单、缺陷列表、日志/截图/RTM、术语表 | **用例清单**：已有（从 nodes 聚合，执行结果列留空） | 用例清单系统提供；其余可链接或附件 | 保持现状：导出含用例表；缺陷/日志/RTM 由用户导出后追加或填链接 |

## 三、是否有必要在系统中提供「所有」内容

- **不必全部在系统内提供**。测试报告中有相当一部分来自「执行后」或「外部系统」（执行统计、缺陷、环境、性能、RTM 等），在 IDE 内预先维护成本高、且与测试/缺陷工具重复。
- **建议在系统内提供的**（高价值、可复用、与画布一致）：
  - **文档控制**：编写/评审/批准人、修订记录、分发与保密（便于多轮导出一致）。
  - **报告摘要**：测试结论、TOP 风险、发布建议（导出即可用，减少手改）。
  - **结论与发布建议**：上线建议、发布门槛（与发布决策强相关）。
  - **风险与豁免**：已知问题、豁免项（常需留痕）。
  - **测试对象与用例**：已支持（从节点自动）；若需执行统计，再扩展 `artifacts.test` 的执行状态（见上表第 7 章）。
- **可选在系统内提供的**：背景与目标、范围说明、策略与方法、环境与配置、测试周期/轮次、关键缺陷摘要（多行文本或链接）。小团队可继续在 Word 中填写。

## 四、在哪里澄清追问和保存

### 4.1 推荐落点：项目蓝图 + 导出时可选覆盖

- **项目蓝图（Project Blueprint）**  
  - 在蓝图内增加 **「测试报告」** 或 **「测试报告元数据」** 区域（可与「全局规则」并列或作为子 Tab）。  
  - 字段建议：  
    - 文档控制：编写人、评审人、批准人、分发范围、保密级别；修订记录（表：版本、日期、修订人、说明）。  
    - 报告摘要：测试结论（枚举：通过/有条件通过/不通过）、TOP 风险（多行）、发布建议（多行）。  
    - 背景与目标：测试背景、测试目标、参考依据（多行，可选）。  
    - 范围与对象：版本/Build、Out of Scope 说明（可选）。  
    - 策略与方法：测试类型、准入/准出标准（可选）。  
    - 环境与配置：环境拓扑、测试数据策略（可选）。  
    - 执行概况：测试周期、轮次说明（可选）。  
    - 缺陷与风险：关键缺陷摘要、已知问题、风险与豁免说明（可选）。  
    - 结论与发布：上线建议、发布门槛、回滚验证说明。  
  - 存储：与现有 `projectMeta` / `globalRules` 一致，持久化到项目 JSON（或单独 `testReportMeta`），导出时传入 `exportTestReport({ projectMeta, nodes, meta })`。

- **导出时行为**  
  - 导出测试报告时，从项目读取上述「测试报告元数据」，填充到对应章节；未填项仍为「（待填写）」。  
  - 可选：导出前弹窗「补充本次报告信息」，仅对部分字段（如本次结论、本次修订说明）做覆盖，不强制。

### 4.2 可选：节点级测试执行状态（用于第 7 章统计）

- 若需在报告内自动生成「计划/已执行/通过/失败/阻塞/跳过」统计：  
  - 在 `artifacts.test` 上扩展，例如：  
    - `cases` 保持为 `string[]`（用例描述）；  
    - 新增 `execution?: Array<{ status: 'passed'|'failed'|'blocked'|'skipped'|'pending'; executedAt?: string }>` 与 `cases` 一一对应。  
  - 澄清与保存位置：**节点详情面板 - 测试 Tab**：在每条用例旁增加「执行结果」下拉（通过/失败/阻塞/跳过/未执行）和可选日期，写入 `artifacts.test.execution`。  
  - 导出时按 `execution` 汇总到第 7 章表格。

### 4.3 小结

- **当前**：导出已按 12 章输出；第 1 章（部分）、第 4 章（测试对象）、第 7 章（用例总数与列表）、第 12 章（用例清单）由系统从 `projectMeta` 与 `nodes` 自动填充；其余章节为占位或通过 `TestReportMeta` 预填（接口已留，UI 未上）。  
- **后续**：在项目蓝图中增加「测试报告」配置区，将上表「建议澄清/保存位置」中的字段落地为表单并写入 `TestReportMeta`，导出时传入即可补全各章；若需第 7 章执行统计，再在节点「测试」中增加执行状态并汇总。
